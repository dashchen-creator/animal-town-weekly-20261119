## 2026-11-19 · C++ 源码迁入与独立构建

- **来源与范围**　从 RR 工作副本 r230 导出 `MegoServer`、`MegoCore`、`MegoProto` 和 `MegoNative`，放在动物镇根目录。服务器配置 C++ 放在 `MegoServer/config/cpp/`。联调使用本地生成的中性数据、测试证书和独立存储。源导入不携带原工程的运行库数据和凭据。[构建与验收入口](/animal-town-weekly-20261119/files/554d89e5340e2c660d712734.md)
- **隔离与编译**　用 `LocalOnly/account-sync/source-migration/src/` 的独立源码副本配置 CMake。该目录及其上一级没有 RRClient，两份 CMake 缓存均不引用 RR 工程路径。protoc 33.4 重生成校验通过 37 份协议。Windows 原生桥源码编译完成，现有原生测试 125 项通过。编译与隔离证据在 `LocalOnly/account-sync/source-migration/` 和 `LocalOnly/cpp-build/standalone/`。
- **构建修正**　显式传入静态 vcpkg 安装路径，优先使用源码自带的 CLI11 和 toml++ 头文件。重编 `http_gate.exe`、`auth_service.exe` 和 `save_server.exe` 成功。候选客户端打包时写入该次联调的回环地址，修正了首次客户端仍只接受旧端口的问题。
- **联网验收**　用本轮的三个程序和 GDExtension 启动 `https://localhost:19743`。A 端通过客户端正常入口登录、完成首单，网关记录 6 次 `/save/player/sync` 返回 HTTP 200。B 端从全新的加密本地库使用同账号登录，恢复相同棋盘、序章和 4 金币。A 端 26 项、B 端 6 项通过。报告在 `LocalOnly/account-sync/cpp-source/windows-source-20261119/clients/20261119-133429-15a5f4f1/cpp-client-report.json`。
- **单机回归**　常规 `Build-Android.bat` 改从动物镇目录读取同版本 Godot，出包 `20261119-115329-aa5bb519`，原内部预览包身份保持一致。签名、对齐、包信息、SHA-256 和源码快照检查通过。APK 和单机快照均未包含 C++ 联网入口或原生桥。上一个已分发单机 APK 保留，实机体验未重测。
- **兼容与范围**　源码联调使用自己的端口、MongoDB、Redis 和测试身份。既有 `19643` 联调服保留原环境。新证据覆盖同机双 Windows 进程，移动联网、公司 SDK 和正式部署待验。

## 2026-11-18 · 独立 C++ 登录与云存档

- **部署**　AnimalTown 自有实例使用 `https://localhost:19643`。`LocalOnly/account-sync/rr-cpp/vendor/` 记录实际服务程序、依赖版本及 SHA-256、共享协议源、原生桥和本地配置表结构。`runtime/` 存动物镇独立配置、测试证书、MongoDB 数据、Redis 会话和日志。RRClient 实例及资料保持只读。用中性合成表满足存档服务启动合同，商城、支付和运营路由未开放。
- **接入**　候选用 RR 原生桥完成会话及 HTTPS/protobuf 通信。Godot 同步提交先写本地待办，由 C++ LevelDB 和可靠队列接管。不同基线会暂停并保留进度。测试凭证和 Python 旧账号、进度互相独立。日常 `client/`、APK 构建入口和单机格式保留。
- **验证**　用正常入口登录 C++ 测试服，A 端实际完成首单获得 4 金币。网关记录 6 次存档同步返回 HTTP 200，B 端从新的加密本地库启动，通过 C++ 云档加载恢复棋盘、序章和金币。A 25 项、B 6 项通过。证据在 `LocalOnly/account-sync/rr-cpp/clients/20261118-185906-3b4e751e/`。验收入口（原始引用未随本次网页发布）
- **待验**　当前为同机双 Windows 客户端、独立匿名测试身份和本机证书固定联调。正式 SDK、物理双设备、远端证书、Android/iOS 原生移植和真实冲突选择界面另做验收。Python 旧档可继续使用原候选查看。

## 2026-11-18 · Windows 测试账号与云存档联调

- **本批变化**　新增独立测试账号服务。`POST /auth/test-session` 给已核验的测试身份签发会话，`GET /save/player/load` 读取所属账号进度，`POST /save/player/sync` 以服务端修订和持久化提交回执保证冲突保护与重复提交幂等。联调版使用 HTTP/JSON 与 SQLite，现有 RR 原生验证继续独立维护。
- **兼容与隔离**　联调版只有候选快照接入账号存储。同步待办和业务快照一起落盘，普通单机源码及构建入口仍使用原本地 JSON。账号首次联网登录，游戏中掉线可继续保存。云端拒绝分叉覆盖，当前客户端保留两边数据并暂停自动同步。
- **验证**　Windows 端 A 使用正式登录控件进入序章。停掉真实监听后，用游戏操作完成第一单并本地获得 4 金币。重启同一服务后收到云确认，端 B 从无本地档状态登录并恢复棋盘、序章进度和金币。真实 HTTP 额外复核缺失身份拒绝、账号隔离、提交重放和旧版本冲突。原机总报告 `LocalOnly/account-sync/online/20261118-182244-393f1f8e/online-report.json`。
- **双包交付**　同一份玩法源另出 Android 单机 APK，原机报告 `LocalOnly/builds/android/20261118-182653-921a7cc9/build-result.json`。比对两份源清单和 APK 签名、哈希及包内资源，单机包保持既有应用 ID，未装入账号联调入口或配置。此包真机体验待验。
- **试玩登录故障**　用户截图提示登录失败。实际本机账号与 SQLite 记录匹配，测试服监听 19443 但健康检查超时。核实进程归属后用同一目录和数据库重启，真实账号登录及云档读取均返回 200。请求日志改写运行目录文件，避免请求处理依赖可暂停的 Windows 控制台输出。账号联调候选移除无效输入框，按服务无响应、身份被拒及其他登录问题分别提示。日常单机启动页及存档保持独立。
- **待验**　两端是同机独立 Windows 进程。物理双设备、远端 HTTPS、Android/iOS 账号包、SDK 绑定、正式部署和业务防作弊需独立验收。基线处于内部联调。
