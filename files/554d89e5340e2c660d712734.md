# 动物镇 Windows C++ 源码构建

动物镇使用自己的 `MegoServer`、`MegoCore`、`MegoProto` 和 `MegoNative`。Windows 联调构建生成网关、认证、存档服务和 Godot GDExtension。服务器读取动物镇维护的测试配置，客户端在独立快照内加载原生桥。内部单机包继续使用项目根目录的 `Build-Android.bat` 和 `Build-Web.cmd -Offline`。

## 工具链

- 安装 Visual Studio 2022 的「使用 C++ 的桌面开发」工作负载、Windows SDK、CMake 3.30 或更高版本及 Python 3.10 或更高版本。
- 准备 vcpkg 的 `x64-windows-static` 安装前缀，包含 Release 和 Debug 库、头文件和 CMake 包配置。依赖版本与覆盖端口见 vcpkg 配置（原始引用未随本次网页发布）和依赖清单（原始引用未随本次网页发布）。有 vcpkg 的环境可从工程根运行下方安装命令。已有同版本的前缀可直接使用。
- 把 Godot 4.7.2 Windows x86_64 标准版的普通和 console 两个 EXE 放入 `LocalOnly/engines/standard-4.7.2/`。Windows 联网包和常规出包工具都从 workspace.json（原始引用未随本次网页发布） 读取引擎路径。
- 运行 C++ 测试服另需 MongoDB 8.0.28、mongosh 2.9.2、Redis 8.10.0、NATS 2.14.4、Nginx 1.31.3 及 OpenSSL。工具目录按下表准备。同机已有旧联调环境时，可将 `LocalOnly/account-sync/rr-cpp/vendor` 传入 `--runtime-tools`。暂存器从中只读取下表的中间件工具。

| 相对工具目录 | 需要的文件 |
| --- | --- |
| `mongo/bin` | `mongod.exe` |
| `mongosh/bin` | `mongosh.exe`、`mongosh_crypt_v1.dll` |
| `redis` | `redis-server.exe`、同发行包的 `msys-2.0.dll`、`msys-crypto-3.dll`、`msys-ssl-3.dll`、`msys-gcc_s-seh-1.dll`、`msys-stdc++-6.dll` |
| `nats` | `nats-server.exe`、`LICENSE` |
| `nginx` | `nginx.exe` |
| `openssl` | `openssl.exe` 和同发行包的 `libcrypto-3-x64.dll`、`libssl-3-x64.dll`，或对应的 1.1 DLL 对 |

```powershell
$packageRoot = Join-Path (Get-Location).Path 'LocalOnly/cpp-build/packages'
$manifestRoot = (Resolve-Path .\MegoServer).Path
vcpkg install "--x-manifest-root=$manifestRoot" "--x-install-root=$packageRoot" --triplet x64-windows-static --host-triplet x64-windows-static
$prefix = Join-Path $packageRoot 'x64-windows-static'
.\tools\build_cpp_stack.ps1 -DependencyPrefix $prefix
```

构建入口把 CMake 中间文件放入 `LocalOnly/cpp-build/source`，并运行现有原生测试。服务端和原生库都使用同一份已生成的协议 C++。协议改动后用固定的 protoc 33.4 重新生成并检查。

```powershell
$protoc = Join-Path $prefix 'tools/protobuf/protoc.exe'
python -B .\MegoProto\export.py --language cpp --check --protoc $protoc
```

## 暂存和验收

以下命令从本轮编译产物创建独立部署。每次暂存填写新的构建编号。命令里的 `$runtimeTools` 指向上表的工具目录。使用 Python 的实际可执行文件，避免命中 Microsoft Store 的占位命令。

```powershell
$runtimeTools = 'LocalOnly/cpp-build/runtime-tools'
$buildId = 'qa-001'
$scripts = 'docs/skills/animaltown-account-sync/scripts'
python -B "$scripts/stage_cpp_stack.py" --id $buildId --dependency-prefix $prefix --runtime-tools $runtimeTools
$env:ANIMALTOWN_CPP_SOURCE_BUILD = $buildId
python -B "$scripts/build_cpp_client.py"
# 将构建器打印的候选目录传给验收脚本。
python -B "$scripts/verify_cpp.py" "<候选目录>"
Remove-Item Env:ANIMALTOWN_CPP_SOURCE_BUILD
```

验收脚本启动本轮服务，走正常游戏入口登录，在 A 端完成首单，再用同一账号从 B 端的新本地库恢复云档。服务和客户端的产物及证据都在 `LocalOnly/account-sync/cpp-source/<构建编号>/`。留给人工试玩时，先用候选目录的 `Start-Cpp-Test-Server.cmd` 起服，再打开 `Play-A.cmd`。关闭 A 后用 `Play-B.cmd` 恢复。停服用同一目录的 `Stop-Cpp-Test-Server.cmd`。

源码联调监听 `https://localhost:19743`，同机一次运行一套源码联调。每个构建编号有独立的证书、账号和数据库。现有导入版仍使用 `19643`。配置 C++ 来自固定的上游生成版本，测试用运行表只装入动物镇合成数据。玩家档、密钥、依赖缓存和中间件程序放在 `LocalOnly`。
