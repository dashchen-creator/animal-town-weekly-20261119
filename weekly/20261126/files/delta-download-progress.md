# Android 小首包与远程资源加载

2026-11-17。v2 供评审，基于当前 Android 导出、车站到早餐亭的玩家入口和早餐分享分包实测。

## 单机游玩中的下一章预取

客户端进入可操作的单机宿主后，在游戏前台的操作间隙串行预取一个包。当前试调从最近一次操作结束约 700 毫秒后开始检查。开棋盘、转场、施工演出和进章等待期间延后发起新的后台下载。

- 序章 PR01 车站可操作后优先预取客栈 C1。进入客栈 IN00 后，下一次空档就预取早餐亭 C2。进章需要的场景和章节包优先于可选音乐。可用本地缓存可直接校验复用。
- 在空档请求现有主备资源源。后台失败不弹窗，按 4、8、16、32 秒间隔重试。游戏失焦或暂停时不启动新任务。再次回到游戏可重新检查。
- 预取用右侧小圆环展示真实进度。城镇里放在设置按钮下方，棋盘里移到资源栏和订单区之间。圆环内上行显示已下量，下行显示总 MB，全区透传触摸，任务结束后收起。
- 玩家主动进章时复用同一资源对象与在途请求。真实进度和当前与总 MB 继续可见。预取本身不开放章或提交进度，进章继续沿用原有校验、挂载、入口检查和存档顺序。

本轮 Windows 隔离测试用 v98 的实际章节 PCK、本机限速镜像和当前工程预取脚本。第一次清单请求失败后，车站棋盘可继续操作。网络恢复后自动完成 C1。玩家在 C1 下载进行中点击出发时，本章资源各只下载一次，校验挂载完成才进章。C2 在 IN00 且 IN01 尚未完成时开始预取，完整挂载后才请求共用音乐。测试证据 `in-play-prefetch-1795610461/trace.json`。已发布 v98 的节点与包体另见下文。下一次 Android 构建仍需真机验证弱网、切后台和实际等待时间。

另用本轮实际生成的缓存续档到 IN10，点击进入早餐亭后进章成功。全程新增资源请求为零，未出现进章等待卡。证据 `in-play-prefetch-warm-1795610599/trace.json`。

角落圆环在 Windows 的 1080×2340 与 1080×1800 下用实际限速下载复测。棋盘回车站操作正常，云幕期间圆环保持同一位置，转场结束后移到车站角落。主动出发时由进章等待卡显示同一笔下载，C1 只下载一次。证据 `prefetch-corner-ring-1795611078/trace.json`。

## 2026-11-25 按玩家解锁顺序分包

**资源下载界面规则。** 首开补丁、章节包、棋盘按需包、音乐等预取，以及试点功能包在下载期间都展示真实进度和「已下载 / 总计 MB」。启动沿用车站票卡，棋盘和章节沿用米洛等待卡和盖章票卡。没有等待页接管时，预取显示角落圆环，普通下载显示可透传触摸的奶油票条。整包命中缓存时跳过下载态。切备用线或重新请求时使用新的传输字节，校验与挂载继续显示对应状态。此规则先落入工程，已经发布的 APK 以其实际版本为准。
