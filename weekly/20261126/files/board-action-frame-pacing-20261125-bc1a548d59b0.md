# v96 发射与合成长帧复验

11 月 25 日复现于内网 v96 和正式累计热更 `r00000007`。普通发射和合成都没有调用 Sort。订单栏顺序计算约 0.1–0.3 ms，FairyGUI 滤镜累计低于 0.4 ms。首轮分段采样抓到同步贴图加载、落格时的阴影像素读取、整页刷新以及重复绘制背景场景。

正式源码沿同一个棋盘入口保留业务提交和主动操作反馈。棋盘准备阶段异步加载近期产出和合成素材。按实际变化刷新格子美术、等级锁区和订单卡。十张正式棋子图集复用与源图及导入纹理一致的阴影边界。棋盘覆盖场景期间，单纯棋子和体力变更延后更新场景 HUD，回场景前恢复。

## Android 同机对照

MuMu 独立实例 3，Android 12，1080×1920，60 Hz。同一 QA 容器先挂载原版 v96 签名热更 `r00000007`，再以本地修复覆盖层复跑同一个客栈 2/10 v4 存档。通过 ADB 注入真实触屏事件，用 SurfaceFlinger 呈现时间戳计算每步操作窗口的最大帧间隔。

| 操作 | 原版最长帧范围 | 修复后最长帧范围 |
| --- | --- | --- |
| 静置 | 17 ms | 17 ms |
| 选中，3 次 | 117–283 ms | 33–67 ms |
| 发射，6 次 | 167–267 ms | 67–83 ms |
| 合成，2 次 | 200–250 ms | 67–100 ms |

超过 100 ms 的操作窗口从 11 个降到 0 个，修复候选仍有一次 100 ms 合成。两轮均完成六次发射和两次合成，体力 100→94。棋盘和资源逐字段对照一致，区别仅为体力与发射器的计时起点。候选包关闭进程并从默认入口重进棋盘后，棋子格位和累计发射、合成次数仍一致，恢复了 1 点离线体力。

证据原件在 `LocalOnly/board-stutter-fix-20261125/`。原版为 `mumu-baseline-result.json`，修复为 `mumu-bounds-result.json`。本地 QA 覆盖层 SHA-256 为 `caa8484faeec621f213da1eb6f593b56574e21bba92047051538ef9c4482fc78`。

正式工作副本另通过 346 项规则检查、56 项新档指针检查和 17 项进盘取消及重进检查。两笔车站订单交付、回到建设入口与动画中取消进棋盘均通过。

正式 Android 交付包仍须在真机复跑冷启动、连续发射和合成、亮灯交单、锁区开解、低体力、进盘取消与关闭重进，并采集实机呈现帧。缺陷保留为待复验。
