# 订单顾客 Spine 与交付衔接

2026-11-25，17:03 路线当前客户端工作副本。沿用五位棋盘顾客的现版造型和裁框。对照工作区 `animaltown-character-spine` v0.4.0、项目反馈闭环和 Foodstars 逐帧复盘（工程内查阅）。

## 范围和实现

- 松鼠和鹰复用现有带眼睑的 Spine 网格，新增交互与交付时间轴。乌栗、眠婶和米洛从实际运行的 PNG 裁区制作头部及局部权重。乌栗和眠婶各有一个紧凑裁框，同角色合计两份网格。裁片对照源图逐像素 RGBA 一致。运行资源为 Spine 4.2 JSON 与图集。
- 当前订单 ID 绑定顾客的入场、待料、招呼、看需求、补齐一项、刚备齐、备齐待交、接物、感谢及退场。备齐触发来自实际需求数量，撤走最后一件材料后回到待料。挂点随宿主更新。
- 成功事务提交后，棋子到本单需求格，顾客回应，旧卡和对应顾客完成退场，金币等资源从原奖励位飞到 HUD。最后一份落到 HUD 后留 140 毫秒反馈，再展示后续订单。已提交的扣发与存档维持现有事务，HUD 用在途差额避免先跳数，离板释放本页演出。
- 短屏顾客招呼使用简短状态句，避免长文案超出底栏。未编制嘴型附件和独立说话动作。

## 证据

- Windows Godot 4.7.2 原生姿势、眨眼、权重、退出与换单共 102 项通过。原两份网格和旧时间轴数据逐项相等。
- 正式登录实点回归覆盖五位顾客、432×720 和 432×1000、合成备齐及撤去材料、两个顾客同屏、写档拒绝后重试、交付中改窗和奖励飞行中退出再进。用本工程已赚取的章节检查点及明示材料前置，不视作从空档通关。
- 第一轮短屏捕获到长句裁尾。另一轮测试在返场云层退完前点合成，已按真实可交互窗口修正回归输入。原失败保留在同一取证目录。
- 当前工作副本 `client/.agents` 有既有修改导致工作区包装入口停在版本校验。用该配置指定的 Godot 及独立项目内存档运行导入和实际入口回归。图查询先遇本地查询脚本路径错位，随后遇独立图数据库权限，受影响调用由当前源码确认。

本轮完成桌面客户端运行验证。Android 实机、导出包及经 Spine 编辑器保存重开后的作者工程仍待验。
